# 알고리즘·자료구조 콘텐츠 형식

현재 집필 범위는 `ch01`~`ch05`의 31레슨(`algorithms-l001`~`algorithms-l031`), 예제 155개와 복습 50개다. 챕터 1~4는 각각 6레슨·30예제, 챕터 5는 7레슨·35예제이며 모든 챕터에 복습 10개를 둔다. 챕터 6~9 목차는 설계다. 이 형식 문서만으로 병합·배포·공개 확인이 끝났다고 판단하지 않는다. [집필 기준](../../docs/AUTHORING.md)과 [과목 문서](../../docs/curriculum/algorithms.md)를 함께 따른다.

## 파일과 생성물

- `ch01/course.json`~`ch05/course.json`: 과목/챕터 ID, 표시 제목, 도달점 설명, 선행 지식, 언어·공식 참고 자료, `lessonFiles`의 집필 파일 순서.
- 각 챕터의 `lesson-01.json`~`lesson-06.json` 및 챕터 5의 `lesson-07.json`: 실제 레슨 본문과 각각 5예제. 챕터 내 `order`는 1부터 실제 레슨 수까지이며 레슨 ID는 전체 과목에서 유일하다. 파일명을 바꿔도 기존 레슨 ID를 바꾸지 않는다.
- 각 챕터의 `review.json`: 10개의 직접 풀기 문항. 챕터별 구성은 아래 표를 따른다.
- 루트 `algorithms-content.js`: 브라우저가 읽는 `window.ALGORITHMS_COURSES` 배열. JSON을 수정한 뒤 생성물도 함께 갱신한다.

| 챕터 | 레슨 ID | 복습 `skill` 접두어와 문항 수 |
| --- | --- | --- |
| 1 · 문제를 절차로 바꾸기 | `algorithms-l001`~`algorithms-l006` | 명세 3 · 절차 추적 3 · 정확성 판단 2 · 경계 입력 2 |
| 2 · 시간과 공간을 세는 법 | `algorithms-l007`~`algorithms-l012` | 성장률 3 · 비용 계산 3 · 공간 2 · 측정 해석 2 |
| 3 · 순서를 저장하는 구조 | `algorithms-l013`~`algorithms-l018` | 구조 원리 3 · 연산 비용 3 · 순서 추적 2 · 구조 선택 2 |
| 4 · 키로 찾는 집합과 맵 | `algorithms-l019`~`algorithms-l024` | 키·동일성 2 · 해시 원리 3 · 비용 조건 2 · 집계 적용 3 |
| 5 · 정렬하고 찾기 | `algorithms-l025`~`algorithms-l031` | 검색 추적 2 · 경계 2 · 재귀 2 · 정렬 원리 2 · 정렬 기준 2 |

복습의 `skill`은 `성장률 · 상한의 뜻`처럼 접두어 다음에 ` · `와 구체적인 목표를 적는다. 검증기는 챕터별 배분과 전체 관련 레슨 연결을 함께 검사한다. 챕터를 추가해도 기존 챕터 JSON과 번들 안의 해당 콘텐츠는 유지한다.

검사와 생성은 Python 표준 라이브러리만 사용한다.

```bash
python3 build-algorithms.py --check-code
python3 build-algorithms.py --check --check-code
node --check algorithms-content.js
```

첫 명령은 검사 후 생성하고, `--check`는 생성물을 쓰지 않고 현재 JSON으로 만든 결과와 바이트 단위로 비교한다. 생성 결과에는 명령 실행 여부나 실행 시각이 들어가지 않는다.

## 레슨과 문항

레슨은 `id`, `order`, `title`, `subtitle`, 양의 정수 `minutes`, `goal`, `intro`, `sections`, `worked`, `misconception`, `keypoints`, `examples`를 가진다. ID·제목·순서는 과목 문서의 해당 챕터와 일치해야 한다.

- `sections`: 3개 이상의 개념 설명. 각 항목은 `title`, 비어 있지 않은 문단 문자열 배열 `body`, 선택적 `code`를 가진다. 먼저 언어 중립 절차나 작은 입력의 상태를 설명하고 필요한 Python 구현을 연결한다.
- `worked`: `question`, 단계별 문자열 배열 `steps`, 결과와 이유인 `answer`, 선택적 `code`를 가진다.
- `misconception`: `question`, `answer`로 오개념과 적용 경계를 설명한다.
- `keypoints`: 비어 있지 않은 핵심 정리 문자열 정확히 3개.
- `examples`: 아래 문항 형식 정확히 5개. 서로 다른 확인 목적을 가지며 문항 요구·예시 답·해설이 일치해야 한다.

예제·복습 문항은 다음 형식을 쓴다.

```json
{
  "skill": "절차 추적 · 누적 합",
  "question": "[2, 3]을 처리한 직후 total을 차례로 적으세요.",
  "code": "total ← 0\n각 value에 대해 total ← total + value",
  "codeKind": "text",
  "solution": {
    "answer": "2 → 5입니다.",
    "code": {
      "kind": "python",
      "source": "total = 0\nfor value in [2, 3]:\n    total = total + value\n    print(total)",
      "output": "2\n5\n"
    }
  },
  "explanation": "total은 이번 값만이 아니라 지금까지 처리한 값들의 합입니다.",
  "related": ["algorithms-l003"]
}
```

`skill`, `question`, `solution.answer`, `explanation`은 필수 문자열이다. `code`는 질문 자료 문자열이며 `codeKind`는 `python` 또는 `text`다. 의사코드·추적표·잘못된 비종료 절차는 `text`로 표시하고, 실행하지 않고 손으로 추적할 자료임을 설명한다. Python 질문 자료는 구문만 자동 검사하므로 요구·예시 답과의 일치 및 실행 결과는 별도로 검토한다.

`related`는 해당 챕터 레슨 ID만 허용한다. 복습에는 한 개 이상이 필수이며 10문항 전체가 해당 챕터의 모든 레슨(챕터 5는 7개)을 연결해야 한다. 검증기는 과목 문서의 실제 레슨 표에서 수량·ID·제목을 읽으며 레슨 수를 일률적으로 6개에 고정하지 않는다. `options`, `optionFormat`, 최상위 `answer`는 쓰지 않는다. 예제·복습은 페이지 안에 세로로 나열하고 각 예시 답·해설을 접어서 제공한다. 손으로 명세·추적·이유를 적거나 PC에서 Python 예시를 작성하며 확인한다. 사이트에는 코드 실행기·자동 채점·점수 표시가 없다.

## 코드 블록과 작성자 실행 검사

본문·작동 예시·`solution.code`의 블록은 `source`, `kind`를 가진다. `kind`는 `text`(의사코드·표) 또는 `python`이다. `caption`은 선택 설명이며 Python 블록에는 정확한 stdout 문자열 `output`을 반드시 둔다. 예상 오류를 다룰 때만 `error`에 `ValueError` 같은 클래스 이름을 적는다. `output`은 마지막 줄바꿈까지 비교한다. 출력이 없으면 빈 문자열을 쓴다.

`--check-code`는 신뢰된 저장소 작성자 Python 블록만 각각 새 임시 폴더의 파일로 만들고, 현재 Python의 격리 모드 `-I`에서 실행한다. 고정 stdin은 빈 문자열이며 시간 제한은 블록당 5초다. stdout과 의도한 오류 종류를 검사하며 정상 예제의 stderr·비정상 종료도 거절한다. 파일·네트워크·사용자 입력에 의존하는 블록은 이 챕터 형식에서 지원하지 않는다. 이것은 임의 사용자 코드를 안전하게 격리하는 실행 서비스가 아니다.

구조·자동 실행 검사는 올바른 문제 명세와 정확성 설명을 대신하지 않는다. 반례가 입력 계약 안에 있는지, 불변식의 시작·유지·종료와 종료 증거가 구분되는지, 빈 목록과 원소 하나의 동작, 브라우저 연결과 기록 보존은 별도로 확인하고 [검증 기록](../../verification.md)에 남긴다.

## 시간·공간과 구조 설명의 기준

챕터 2의 비용은 세는 기본 연산·입력 크기·경우를 밝힌다. 빅오는 성장의 상한이며 대표적인 가까운 상한과 정확한 횟수를 구별한다. 최선·평균·최악은 경우에 관한 설명이고 평균에는 입력 분포 가정이 필요하다. 분할 상환 비용은 연속한 연산의 총비용에 근거하며 무작위 입력 평균과 같지 않다.

공간은 입력·반환값·추가 저장소의 포함 범위와 칸/참조/비트 중 모델을 밝히고 동시에 필요한 최대량을 센다. 실제 `timeit` 결과나 메모리 바이트 수는 환경별 관측이다. 고정 출력과 다르므로 초 단위 수치를 Python 블록의 정답으로 저장하지 않는다. 측정 절차는 읽기 전용 `text` 자료로 설명하거나, 환경·반복·입력·측정 범위를 정한 별도 검증 기록에 남긴다.

챕터 3은 연속한 참조 슬롯과 원소 객체의 위치를 구분한다. 동적 배열의 두 배 확장은 원리 설명 모델이며 CPython의 정확한 증가 규칙을 보장하지 않는다. 연결 리스트의 삽입·삭제는 위치 탐색과 연결 갱신 비용을 합쳐 설명하고, 유효한 선행 노드 참조를 이미 아는 가정을 생략하지 않는다. `deque`의 양끝 연산이 빠르다는 특성을 가운데 인덱스 접근까지 일반화하지 않는다. 스택·큐의 계약과 이를 실현하는 저장 방법을 분리한다.

챕터 4의 버킷·나머지·체이닝 모형은 원리 설명이며 Python dict 내부 배치의 재현이 아니다. 같은 키라면 같은 해시가 필요하지만 같은 해시가 키 동일성을 보장하지는 않는다. 키의 해시·비교 안정성, 충돌과 부하율, 한 번의 재배치 비용과 연속 연산 비용을 구별한다. 문자열 해시의 실제 숫자·set의 순회 순서는 고정 출력으로 저장하지 않는다. 출력이 필요하면 명시한 순서로 조회하거나, 비교 가능한 같은 종류의 값에 한해 정렬해 표시한다.

챕터 5는 정렬 전제와 검색 계약(일치 하나·첫 위치·삽입 경계)을 밝힌다. 이진 탐색의 포함/제외 경계를 혼용하지 않고 빈 입력과 중복·끝 삽입 위치를 확인한다. 재귀는 기저 조건·엄격한 문제 축소·반환 흐름을 설명하고, 전체 호출 수와 최대 동시 호출 깊이를 구분한다. 병합 정렬은 정렬된 부분 결과와 추가 버퍼·호출 스택을 함께 계산한다. 안정성은 같은 정렬 키의 원래 순서를 보존하는 뜻이며 `reverse=True`, 복합 키·동점 처리와 원본 변경 여부도 확인한다.
