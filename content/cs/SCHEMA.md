# CS 콘텐츠 형식

CS 원본은 `content/cs/chNN/`의 JSON이다. 챕터 메타데이터와 레슨 파일, 복습을 `build-cs.py`가 읽어 운영용 `cs-content.js`를 만든다. 현재 콘텐츠 범위는 `cs-ch01`~`cs-ch02`의 `cs-l001`~`cs-l010`이다. 챕터 1은 챕터 2와 같은 초보 안내·실제 도식·문항 지시/답 형식으로 개정하고 PR #29 / SHA `5d0210c`의 main 병합·Pages 배포를 완료했으며 공개 PC·모바일 확인을 완료했다. 다른 챕터는 설계와 실제 구현을 구분한다. [집필 기준](../../docs/AUTHORING.md)과 [CS 과목 문서](../../docs/curriculum/cs.md)를 함께 따른다.

## 파일과 생성물

- `course.json`: 챕터 메타데이터와 학습 순서대로 나열한 `lessonFiles`.
- `lesson-NN.json`: 레슨 본문과 예제 정확히 5개.
- `review.json`: 챕터 복습 정확히 10개를 담은 배열.
- `python3 build-cs.py`: 원본을 검증하고 `cs-content.js`를 생성한다.
- `python3 build-cs.py --check`: 원본 검증과 생성물 바이트 일치를 확인하며 파일을 쓰지 않는다.

생성물은 `window.CS_COURSES` 배열과 첫 챕터의 `window.CS_CH01` 별칭을 제공한다. 챕터 객체에서 `lessonFiles`를 제거하고 해당 파일을 읽은 `lessons` 배열 및 `review` 배열을 넣는다. 한글을 보존하는 JSON을 쓰며 U+2028·U+2029는 JavaScript 문자열 안에서 escape한다. 생성물을 직접 편집하지 않는다.

## 챕터 메타데이터

| 필드 | 형식과 규칙 |
| --- | --- |
| `id` | `cs-chNN`. 폴더와 `slug`에 일치하는 고유 ID |
| `slug` | 폴더명과 같은 `chNN` |
| `number` | 양의 정수. `ch01`이면 1 |
| `title` | 과목 문서의 챕터 제목과 일치하는 비어 있지 않은 문자열 |
| `description`, `prerequisite`, `runtime` | 비어 있지 않은 문자열. 첫 챕터에 프로그래밍 선행이나 실행 환경 설치를 요구하지 않음 |
| `lessonFiles` | `lesson-NN.json` 형식의 평면 파일명 배열. 중복 없이 과목 문서의 레슨 순서·수량과 일치 |
| `references` | 선택 배열. 각 항목에 비어 있지 않은 `title`·HTTPS `url` |
| `referenceCheckedAt`, `validationEnvironment` | 실제 확인한 경우만 쓰는 선택 문자열. 기존 설계의 참고 링크를 새로 검증했다고 표현하지 않음 |

기존 ID는 레슨 재배치나 제목 변경으로 다시 부여하지 않는다. 새 챕터 집필 시 과목 문서의 ID·제목·순서와 실제 콘텐츠를 함께 확인한다.

## 레슨

| 필드 | 형식과 규칙 |
| --- | --- |
| `id`, `title` | 과목 문서의 해당 레슨 ID·제목과 일치 |
| `order` | `lessonFiles` 안의 1부터 시작하는 정수 순서 |
| `minutes` | 읽기 시간의 양의 정수 추정치 |
| `subtitle`, `goal`, `intro` | 비어 있지 않은 문자열. 목표와 필요성, 선행 연결을 설명 |
| `sections` | 3개 이상의 개념 설명 배열. 각 항목은 `title` 문자열과 비어 있지 않은 `body` 문자열 배열, 선택 `code` 도식 |
| `worked` | `question` 문자열, `steps` 문자열 배열, `answer` 문자열과 선택 `code` 도식. 중간 판단 과정을 설명 |
| `misconception` | 비어 있지 않은 `question`·`answer` 문자열 |
| `keypoints` | 비어 있지 않은 문자열 정확히 3개 |
| `examples` | 아래 문항 객체 정확히 5개 |

첫 챕터는 컴퓨터 사용 사례를 읽고 분류·추적·설명하는 학습이다. 자료형·조건문·함수 같은 프로그래밍 문법을 이미 안다고 가정하지 않는다. 개념의 의미와 이유를 본문에서 가르친 뒤 문제에서 확인한다.

## 예제·복습 문항

| 필드 | 형식과 규칙 |
| --- | --- |
| `skill` | 확인할 개념을 나타내는 비어 있지 않은 문자열 |
| `question` | 학습자가 분류·설명·추적할 요구를 담은 비어 있지 않은 문자열 |
| `instructions` | 데이터 형식상 선택인 비어 있지 않은 문자열 배열. 있으면 형식을 검사한다. 풀이 전에 보여 주는 작업 순서이며 집필 규칙상 챕터 1~2의 모든 예제·복습에 필수 |
| `answerFormat` | 데이터 형식상 선택인 비어 있지 않은 문자열. 있으면 형식을 검사한다. 학습자가 적을 항목·단위·빈칸 형식이며 집필 규칙상 챕터 1~2의 모든 예제·복습에 필수 |
| `visual` | 선택 시각 자료 객체. 아래 cells·flow·table 형식 |
| `solution.answer` | 가능한 예시 답을 담은 비어 있지 않은 문자열 |
| `explanation` | 예시 답의 이유와 판단 기준을 담은 비어 있지 않은 문자열 |
| `exerciseType` | 선택값 `explain`. 첫 챕터에 코드 구현·실행 문제를 넣지 않음 |
| `code`·`codeKind` | 질문에 읽기용 도식이 필요할 때만 함께 사용. `code`는 비어 있지 않은 문자열, `codeKind`는 `text` |
| `solution.code` | 선택 읽기용 text 도식 객체 |
| `related` | 같은 챕터의 레슨 ID 배열. 중복 불가, 복습은 1개 이상 필수 |

객관식 `options`·`optionFormat`이나 문항 최상위 `answer`를 쓰지 않는다. 정답은 `solution.answer`에 둔다. 화면은 문제를 세로로 나열하고 각 예시 답·해설을 기본 접힌 상태로 제공한다. 자동 채점·점수·사이트 내부 실행기는 제공하지 않는다.

복습 10개는 모든 레슨을 적어도 한 번 `related`로 연결한다. 챕터 1 설계의 계층 구분 3개·상태 추적 3개·인터페이스 적용 3개·오개념 1개를 기준으로 본문 목표와의 연결을 사람이 확인한다. 예제의 단어만 바꾼 복제로 채우지 않는다.

챕터 2는 표현 원리 3개·바이트 해석 3개·형식 선택 3개·오개념 1개다. 두 챕터 모두 글자 수 제한은 두지 않는다. 새 개념과 판단·계산 방법을 본문·작동 예시에서 먼저 가르치고, 문제의 조건과 해야 할 일, 답을 적는 형식을 구체적으로 쓴다. 관찰 대상·시점·가능한 결론을 명시하고, 고쳐 쓰기 문제에는 고칠 문장과 유지할 조건을 준다. 답 형식은 빈칸이나 항목명으로 안내하며 정답을 미리 채우지 않는다.

## 핵심 강조와 시각 자료

일반 설명·문항의 `**핵심 단어 또는 문장**`은 강조로 표시한다. 임의의 Markdown·HTML 삽입은 지원하지 않는다. UI는 텍스트를 먼저 escape하고 짝을 이룬 `**...**`만 `strong`으로 바꾼다. `code.source`와 문항의 `code`는 원문 그대로 표시한다.

`sections`의 각 항목, `worked`, 예제·복습 문항에 `visual`을 둘 수 있다. `worked`에도 선택 `instructions`·`answerFormat`을 둘 수 있다. 시각 자료는 제목과 설명을 가진 figure로 표시하며 색상만으로 의미를 전달하지 않는다. 챕터 1~2는 모든 레슨에 실제 상자·흐름·표를 넣고 본문에서 읽는 순서와 뜻을 설명한다. 본문과 문제에서 같은 이름·상태·읽는 순서를 사용하고 그림만으로 처음 보는 개념을 추측하게 하지 않는다.

```json
{
  "type": "cells",
  "title": "이진수 101의 자리값",
  "items": [
    {"label": "4의 자리", "value": "1", "note": "4를 더함"},
    {"label": "2의 자리", "value": "0", "note": "더하지 않음"},
    {"label": "1의 자리", "value": "1", "note": "1을 더함"}
  ],
  "caption": "왼쪽부터 읽습니다. 1이 적힌 자리의 값을 더하면 4 + 1 = 5입니다."
}
```

- 공통 필수 필드: `type`, 비어 있지 않은 `title`·`caption`.
- `cells`·`flow`: 비어 있지 않은 `items` 배열. 각 항목은 비어 있지 않은 `label`·`value`, 선택 `note` 문자열. `flow`는 항목 순서대로 화살표를 붙인다.
- `table`: 비어 있지 않은 `headers` 문자열 배열과 `rows` 배열. 각 행은 헤더와 같은 길이의 비어 있지 않은 문자열 배열이다.
- 시각 자료와 항목에 정의하지 않은 필드는 거부한다. 이미지 URL·HTML·스크립트 입력은 지원하지 않는다.
- 좁은 화면에서는 셀·표를 내부 스크롤로 읽고 흐름은 세로로 읽는다. 표에 열 제목을 두고, 스크롤 영역은 키보드로 접근할 수 있게 한다.

## 읽기용 text 도식

기존 표시 구조와 호환되는 `code` 필드를 읽기용 텍스트 자료에 사용할 수 있지만 프로그래밍 코드나 실행기는 아니다. 화살표를 글자로 적은 text 블록은 실제 시각 자료 `visual`과 구분한다. 챕터 1~2의 관계·상태·비교를 보여 줄 때는 위의 cells·flow·table 도식을 사용한다.

```json
{
  "kind": "text",
  "source": "사용자 행동 → 응용 프로그램 → 운영체제 → 하드웨어",
  "caption": "각 층이 맡은 책임을 따라 읽는 개념 도식입니다."
}
```

`kind`는 반드시 `text`, `source`는 비어 있지 않은 문자열이다. `caption`은 선택 문자열이다. 결과를 포함한 전체 도식을 `source`에 적으며 별도의 `output`·`error`나 실행 파일·입력 자료를 선언하지 않는다. 텍스트는 UI에서 escape해 표시하며 HTML을 직접 삽입하지 않는다.

## 검증 범위

빌더는 파일 누락, JSON 구조·타입·빈 값, 챕터·레슨 ID/제목/순서, 중복 파일·ID, 레슨 예제 5개·핵심 정리 3개, 복습 10개·관련 ID·전체 레슨 연결, 읽기용 text 블록, 지시·답 형식, 시각 자료 타입·필수 텍스트·표의 열 수를 검사한다. 기존 데이터와의 호환을 위해 `instructions`·`answerFormat`은 빌더의 필수 필드로 바꾸지 않으며, 필드가 있으면 그 형식을 검사한다. 집필 규칙상 챕터 1~2의 모든 예제·복습에는 두 필드를 작성하고, 실제 작성 여부와 화면 표시는 별도 브라우저 검사로 확인한다. 코드 실행 검사는 없다.

개념의 정확성, 본문에서 문제로 이어지는 난이도, 도식과 설명의 일치, 예시 답·해설, 복습 분포, PC·모바일 가독성, 연결 경로·읽음·기록 이동은 별도로 검토한다. 원본 검증과 생성물 일치만으로 브라우저 동작이나 공개 배포 성공을 주장하지 않는다.
