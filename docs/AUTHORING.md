# 챕터·레슨 집필 기준

## 학습 난이도와 중간 단계

난이도는 글·코드 길이보다 동시에 유지할 상태·조건과 본문에서 문제로 옮길 때의 추론 거리로 판단한다. 새 표현과 새 전략을 한꺼번에 독립 설계하게 하기 전에 작은 입력의 상태 변화와 갱신 순서를 보여 준다. 접힌 정답만으로 사전 발판을 대신하지 않는다. 이미 배운 원리의 한 조건을 바꾸는 연습은 유지하며, 새 상태 모델이 필요한 경우 별도 레슨으로 나눈다. 현재 알고리즘 변경의 구체적인 범위는 [학습 단계 보완 계획](ALGORITHMS-PROGRESSION.md)을 따른다.

최초 설계 기준일: 2026-11-10 (한국 시간). 아래 기준은 본문 집필과 후속 구현에 사용하며, 실제 구현 범위는 `START-HERE.md`와 담당 과목 문서에서 확인한다.

## 구조와 ID

`대분류 → 챕터 → 레슨`이 기본 구조다. 수학처럼 범위가 넓거나 이미 공개된 과정은 챕터 안에 단원을 둘 수 있다. C++/#는 대분류 아래 두 독립 트랙을 두고 각 트랙에 챕터를 둔다. 트랙이나 단원은 예제·복습 수량을 바꾸지 않는다.

- 대분류 ID는 `subjects.js`의 현재 ID를 유지한다.
- 새 챕터 ID는 `<subject-id>-chNN`, 새 레슨 ID는 `<subject-id>-lNNN`을 기본으로 처음 부여한다. 표시 순서와 식별자는 별개이며, 이후 이동/제목 변경으로 기존 ID를 재부여하지 않는다.
- 기존 수학 중1의 `prime` 등 레슨 ID는 그대로 사용한다. 문서의 중1 챕터 식별자와 실제 `/math/middle-1` 경로는 명시적으로 연결한다.
- 각 레슨에는 주된 이해·수행 목표 하나가 있어야 한다. 여러 독립 주제를 한 레슨 제목에 쌓지 않는다.
- 각 챕터는 하나의 의미 있는 완료 지점을 갖고, 기본적으로 4~6개 레슨 정도로 나눈다. 필요한 범위에 따라 조절하며 획일적인 수량을 맞추기 위해 주제를 잘라내지 않는다.

## 범위별 깊이

| 범위 | 기대하는 끝점 | 넘기지 않을 선 |
| --- | --- | --- |
| 기초 한정 | 핵심 용어·원리를 설명하고 작은 예제를 읽거나 실행·수정하며 한계를 구별한다 | 고급 최적화, 대규모 운영, 프레임워크 생태계 전체, 연구 논문 수준까지 확장하지 않음 |
| 중고급 | 기초를 바탕으로 코드 구조·오류·성능·의존성 등을 판단하고 작은 산출물을 검증·배포·유지한다 | 기초 문법을 처음부터 재강의하거나 모든 전문 분야를 포괄하지 않음 |
| 기초→실무 | 입문 개념부터 시작해 해당 분야의 대표적인 실제 작업을 스스로 수행·확인·수정한다 | 실무라는 이유로 기업 규모 플랫폼, 모든 도구, 자격시험·연구 전부를 포함하지 않음 |

‘실무’는 강좌를 읽기만 하면 취업·전문가 수준이 보장된다는 뜻이 아니다. 예를 들어 SQL은 요구에 맞는 질의·스키마·트랜잭션을 작성하고 점검하는 수준, vim은 실제 코드 파일을 탐색·수정하는 수준으로 과목별로 정의한다.

## 레슨 본문 구성

1. **필요성과 질문**: 해결하려는 상황과 ‘왜’ 한 가지를 제시한다.
2. **선행 연결**: 앞에서 배운 어떤 개념을 쓰는지 짧게 알려 준다. 모르는 경우 돌아갈 레슨을 연결한다.
3. **원리 설명**: 단계별 설명, 작은 값/코드, 필요하면 정확한 그림·표로 원인과 결과를 보여 준다.
4. **풀이/작동 예시**: 결과만 제시하지 말고 중간 상태와 판단 이유를 보인다.
5. **오개념과 경계**: 자주 혼동하는 조건, 반례 또는 적용되지 않는 경우를 설명한다.
6. **핵심 정리**: 나중에 복습할 때 사용할 짧은 정리와 판단 기준을 남긴다.
7. **예제 5개**: 아래 목적을 섞어 이해를 확인한다.

기존 중1 구현은 3개의 개념 단계·3개의 핵심 정리·4지선다 5개라는 별도 데이터 형식이 있다. 이것은 중1의 호환 계약이다. 다른 과목의 글을 억지로 같은 JSON 필드에 넣기 전에 해당 구현 작업에서 콘텐츠 모델과 UI를 정한다. 사이트 기능을 새로 만들지 않고 집필만 하는 작업에서는 설명·코드·문제·해설을 완전한 자료로 남긴다.

파이썬은 사용자가 PC에서 직접 타이핑한다는 요청에 따라, 예제와 복습 문항을 페이지에 세로로 나열한다. 각 문제는 직접 코드 작성·실행·수정 또는 결과와 이유 설명을 요구하고, 예시 답·해설은 개별적으로 접힌 상태에서 펼쳐 확인하게 한다. 객관식 선택·퀴즈 모달·자동 채점·점수 표시를 쓰지 않는다. 후속 파이썬 레슨과 챕터도 이 형식으로 이어가며, 수학 중1의 객관식 형식을 변경하지 않는다.

## 레슨당 예제 5개

알고리즘·자료구조의 알고리즘/기법 명칭은 `DFS(깊이 우선 탐색)`, `BFS(너비 우선 탐색)`, `DP(동적 계획법)`, `Merge Sort(병합 정렬)`처럼 영어 또는 표준 약어를 먼저 쓴다. 제목·목차·독립된 질문에서 첫 명칭을 함께 표시하고, 동일 문구 안의 반복은 영문으로 줄일 수 있다. 약어의 전체 영어 이름은 관련 본문에서 소개한다. 설명을 위해 한글로 풀어 쓴 이름만 남겨 표준 영어 명칭을 숨기지 않는다. 표시명을 고치면서 코드·입출력·식별자를 함께 바꾸지 않는다.

| 역할 | 수학 예시 유형 | 프로그래밍/도구 예시 유형 |
| --- | --- | --- |
| 1. 뜻 | 개념이나 조건 구별 | 용어·명령·구문이 하는 일 |
| 2. 해석 | 그림·식의 의미 읽기 | 짧은 코드/출력/실행 흐름 예측 |
| 3. 이유 | 성립 이유·반례 | 오류 원인·선택 이유·성립 조건 |
| 4. 작은 적용 | 간단한 계산·식 세우기 | 한 부분 수정·작은 질의·명령 선택 |
| 5. 전이 | 값·조건이 바뀐 상황 | 작은 요구 변경·다른 입력·경계 사례 |

이는 기본 구성 제안이며 과목에 맞게 조정할 수 있다. 한 번에 새 개념 여러 개를 요구하는 난문 대신 배운 원리를 다른 상황에서도 쓸 수 있는지 확인한다. 각각 정답/기대 결과와 이유를 포함한다. 서술·코드 작성 형태를 계획할 수 있으나 브라우저 코드 실행기나 자동 채점 기능이 생겼다고 가정하지 않는다. 코드 예제는 지정 환경에서 실행 검증하고 입력·출력·전제 조건을 기록한다.

파이썬의 예제 5개는 하나씩 다음 화면으로 넘기는 문제가 아니라 레슨 안에서 연속해서 읽는 목록이다. 질문에는 무엇을 직접 적거나 실행할지 명확히 쓰고, 예시 답은 가능한 풀이 한 가지로 제시한다. 같은 요구를 충족하는 다른 코드도 가능하다는 점을 해설에 반영한다. 답을 먼저 보여 주지 않도록 예시 답과 해설을 함께 접으며, 학습자가 자신의 결과와 비교할 출력·판단 기준을 남긴다. 문항 형식은 [파이썬 콘텐츠 형식](../content/python/SCHEMA.md)을 따른다.

알고리즘·자료구조의 레슨별 예제는 사용자가 정한 구성을 따른다. 1번은 중요한 개념을 설명하는 논술형이고, 필요할 때만 2번까지 논술형으로 둔다. 나머지 예제는 PC에서 알고리즘 함수를 직접 작성하고 실행하는 구현 문제다. 함수 이름·허용 입력·반환값·경계 조건·입력 변경 여부와 2~4개 확인 사례를 제시한다. 완성 코드는 접힌 예시 풀이에만 두며 독립 실행 가능한 함수와 확인 호출·예상 출력을 제공한다. 질문에 완성 코드를 주고 출력만 묻는 형태로 구현 문제를 대체하지 않는다. 난도는 해당 레슨에서 배운 원리와 작은 요구 변경 안에서 조절한다. 이 구성은 위의 일반적인 5역할 표보다 우선하며, 챕터 복습의 문항 수와 기존 설계는 별도로 유지한다.

## 챕터 복습 10개

- 챕터 문서의 ‘복습 10문제 설계’를 문제별 청사진으로 풀어 쓴다. 실제 작성 시 각 문항에 목표, 관련 레슨 ID, 정답·해설을 연결한다.
- 모든 핵심 목표가 적어도 한 번 등장하도록 매핑하고, 서로 연결되는 원리는 한 문항에서 함께 확인할 수 있다. 10개에 담을 수 없을 만큼 독립 핵심이 많다면 새 챕터의 분할을 검토한다.
- 예제와 숫자/단어만 바꾼 복제 10개로 채우지 않는다. 뜻·관계·해석·적용·오개념을 섞고, 일부 문항은 앞 레슨들을 연결한다.
- 풀이 뒤에 필요한 개념 요약과 관련 레슨으로 돌아갈 수 있게 한다. 복습 페이지 자체가 재학습의 출발점이 되어야 한다.
- 기존 중1 한 챕터는 보존한다. 8단원·30레슨을 10문제로 복습하므로 단원 핵심을 연결하는 요약 점검이며 모든 세부 기능의 숙달을 각각 보장하지 않는다. 필요한 세부 개념은 해당 레슨의 5예제로 연결한다.
- 복습 10문제와 선택 실무 과제는 구분한다. 과제가 필수라면 요구 결과와 확인 기준을 명시하고, 복습 문항 수를 임의로 대체하지 않는다.
- 파이썬 복습도 같은 세로 목록 형식으로 10문항을 제공한다. 각 문항에 접힌 예시 답·해설과 관련 레슨 연결을 두고, 점수 대신 실행 결과와 원리를 스스로 대조할 수 있게 한다.

## 중복과 선행 지식

각 개념에는 깊게 설명할 담당 과목을 둔다. 다른 과목은 자기 목적에 필요한 짧은 설명·예시·링크를 제공한다. 예를 들어 웹에서 HTTP 요청을 쓰지만 프로토콜·재시도 정책 전체를 재강의하지 않고 HTTP·API·SDK를 연결한다.

‘선행: 파이썬’처럼 과목 전체 완주를 모호하게 요구하지 않는다. ‘변수·함수·리스트를 읽을 수 있음’처럼 필요한 개념을 적고, 목차가 안정되면 특정 레슨으로 연결한다. 상호 참조가 있어도 입문 챕터가 서로의 실무 챕터를 요구하는 순환 의존은 만들지 않는다.

다른 과목의 개념을 연결할 때 그 과목의 예제 언어까지 필수 선행으로 만들지 않는다. 예를 들어 C++/C# 트랙에서 파일·직렬화 개념을 연결하면 해당 언어의 짧은 예로 보충하며, Python 문법 학습을 강제로 요구하지 않는다. 도구·언어가 다른 연결에는 개념 설명과 문법 의존을 구분한다.

## 버전과 도구

- 환경·제품·라이브러리·CLI 사용법은 집필 시 공식 문서를 확인한다. 검증한 버전/운영체제/명령을 기록한다.
- 오래 유지되는 개념을 먼저 설명하고, 특정 도구의 설정·화면·버전별 차이를 분리한다.
- C++와 C#, Windows와 Linux, x86-64와 다른 ISA의 문법·실행 환경을 섞어 설명하지 않는다.
- 파일 삭제·덮어쓰기·Git 이력 변경·서비스 설정 예제는 연습용 파일/저장소에서 재현하고 영향과 복구 방법을 함께 설명한다.
- 예제에 실제 자격증명·개인 데이터·유료 서비스 가입을 필수로 넣지 않는다. 필요한 외부 연동은 해당 구현 범위에서 별도로 다룬다.
- 파이썬의 `build-python.py --check-code`는 본문·풀이 예시와 문항의 `solution.code` 중 Python 블록을 검증한다. 질문에 있는 코드 문자열과 콘솔 기록은 자동 실행 대상이 아니므로 질문의 전제·예시 답·해설의 일치도 별도로 확인한다. PC 직접 실습과 사이트의 코드 표시를 구분한다.

## 콘텐츠 완료 기준

아래 기준은 작업 범위별로 적용한다. 레슨 한 개 집필에는 그 레슨의 본문·예제 검증을, 챕터 완료에는 복습 10개 검증을, UI 구현/공개에는 화면·상태·기록 보존 검증을 적용한다. 레슨 집필만 요청받았다고 챕터 전체나 새 UI까지 자동으로 확장하지 않는다.

| 확인 영역 | 통과 기준 |
| --- | --- |
| 범위 | 지정 과목의 기초/중고급/실무 상한과 레슨 목표에 맞음 |
| 설명 | 이유·중간 과정·조건이 연결되고 처음 나오는 용어를 설명함 |
| 수학/코드 | 계산·예상 출력·예외 조건·명령 결과를 독립적으로 확인함 |
| 예제 | 정확히 5개, 서로 다른 확인 목적, 답과 이유가 일치함 |
| 파이썬 문제 형식 | 예제 5개·복습 10개가 각각 세로 목록이며, 개별 예시 답·해설이 접혀 있음. 직접 작성·실행·수정하는 요구가 명확하고 객관식·퀴즈 모달·점수 표시가 없음 |
| 복습 | 챕터당 10개, 핵심 목표와 관련 레슨 연결, 세부 숙달의 한계를 과장하지 않음 |
| 시각 자료 | 도식·표의 값과 설명이 일치하며 존재하지 않는 그림을 언급하지 않음 |
| 화면 | PC·모바일에서 읽기 쉽고 긴 코드·표·수식이 전체 화면을 깨뜨리지 않음 |
| 연결/상태 | 링크·이전/다음·진도 상태가 정확하고 미작성 수업을 완료로 표시하지 않음 |
| 보존 | 기존 중1 콘텐츠·ID·URL 호환·브라우저 기록을 유지함 |
| 기록 | 실제 작성·검증한 범위와 남은 작업이 구분되어 있음 |

## 상태를 기록하는 방법

설계 문서의 `콘텐츠 상태`는 문서 작성 자체와 수업 공개 여부를 분리한다. 후속 작업이 진행되면 과목 문서 아래에 구현 현황 표를 두고 ID별 `설계만 / 집필 중 / 검증 완료 / 공개`와 실제 파일·경로를 기록한다. ID가 같다는 이유만으로 구현되었다고 간주하지 않는다.
