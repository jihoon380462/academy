## 우리가 만드는 것

사용자가 스스로 공부하는 개념·원리 중심 학습 사이트다. 먼저 ‘무엇인가, 왜 필요한가, 왜 이렇게 되는가’를 이해하고, 작은 예제로 확인한 뒤 자기 작업에 적용하게 한다. 난도는 어려운 킬러 문제를 푸는 능력보다 설명·관찰·구현·검증 능력이 깊어지는 방향으로 올린다.

PC와 모바일에서 모두 읽고 사용할 수 있어야 한다. 여백 중심의 교과서 디자인을 바탕으로 기본 아이보리·포레스트 및 6개 다크 테마를 설정에서 선택한다. 주제의 실무 수준이 높아져도 설명은 작은 단위로 나눈다.

파이썬 작업의 출발점은 [과목 문서](curriculum/python.md), [콘텐츠 형식](../content/python/SCHEMA.md), `content/python/ch01/`·`content/python/ch02/`·`content/python/ch03/`·`content/python/ch04/`·`content/python/ch05/`·`content/python/ch06/`·`content/python/ch07/`·`content/python/ch08/`·`content/python/ch09/`이다. `python3 build-python.py --check-code`로 본문·풀이 예시·문항의 예시 답에 있는 Python 코드의 출력·오류·실행 후 파일을 확인하고 `python-content.js`를 생성한다. 묶음은 `window.PYTHON_COURSES` 배열이며 `window.PYTHON_CH01`·`window.PYTHON_CH02`·`window.PYTHON_CH03`·`window.PYTHON_CH04`·`window.PYTHON_CH05`·`window.PYTHON_CH06`·`window.PYTHON_CH07`·`window.PYTHON_CH08`·`window.PYTHON_CH09` 별칭을 함께 제공한다. 화면과 접힌 예시 답·해설은 `python-ui.js`·`python.css`, 라우팅·읽음·최근 레슨 기록 연결은 `app.js`에 있다.

파이썬에서는 문제를 고르고 제출하는 화면을 만들지 않는다. 사용자가 PC의 편집기에서 직접 입력하고 실행한 뒤 각 문제의 예시 답·해설을 확인하는 것이 확정된 방식이다. 모바일에서도 문제·본문·해설을 읽을 수 있게 하며, 사이트 내부 코드 실행기나 자동 채점이 있다고 가정하지 않는다. `input()`의 예시 입력과 여러 파일 실습의 실행 파일명·함께 둘 파일·실행 후 파일은 읽기 전용이다. 학습자는 PC에서 파일을 준비하고 입력·실행하며, 가상환경의 실제 경로와 패키지 관리 대상도 자기 환경에서 확인한다.

## 알고리즘·자료구조를 이어서 작업할 때

알고리즘 이름은 사용자 요청에 따라 영어 또는 표준 약어를 먼저 적고 한글 뜻을 괄호에 붙인다. 제목·목차·본문·독립 질문에서 `DFS(깊이 우선 탐색)`, `BFS(너비 우선 탐색)`처럼 찾을 수 있어야 한다. 명칭 개편은 PR #21 / SHA `f732cc3`의 main 병합·Pages 배포·공개 PC/모바일 확인을 완료했다. 정확한 근거는 검증 기록을 따른다.

사용자는 레슨별 예제의 1번(중요한 경우만 2번까지)을 논술형으로, 나머지는 직접 알고리즘 함수를 작성하는 구현 문제로 바꾸도록 확정했다. 함수 계약과 확인 사례를 문제에, 완성 예시 구현·출력을 접힌 풀이에 둔다. 전체 54레슨에 적용해 설명 55개·직접 구현 215개로 개편했다. PR #19 / SHA `4a0beee`의 main 병합·Pages 배포·공개 PC/모바일 확인을 마쳤으며 정확한 검증 범위는 검증 기록을 따른다.

사용자는 1챕터부터 순서대로 진행하기로 했다. 현재 소스는 `algorithms-ch01`~`algorithms-ch09`의 56레슨이다. ch03의 l055와 ch08의 l056은 새 ID이며 기존 ID 숫자순과 학습 순서는 다르다. 이번 변경의 검증·공개 상태는 최근 기록을 확인한다. 추가 집필은 사용자 요청에 따르며 미구현 챕터 10이 있다고 가정하지 않는다. ## 학습 기록 이동을 이어서 작업할 때

사용자 안내는 ‘기록은 이 브라우저에 저장되며, 설정에서 다른 기기로 옮길 수 있습니다’다. 원래 기기에서 설정의 ‘학습 기록 옮기기’로 파일을 저장하거나 복사 코드를 만들고, 다른 기기의 같은 설정에서 파일을 선택하거나 코드를 붙여 넣는다. 파일 선택 시 표시되는 미리보기 또는 코드 붙여넣기 후 ‘가져올 기록 확인’으로 열리는 미리보기를 확인하고, ‘기존 기록과 합쳐 가져오기’를 눌러 반영한다. 사이트는 기록을 서버로 보내지 않으며 사용자가 직접 자료를 전달한다.

읽음 표시는 합집합으로 합친다. 읽음 취소는 전파하지 않으므로 오래된 자료의 읽음이 다시 추가될 수 있다. 최고 점수는 더 높은 값을, 최근 점수는 풀이 날짜가 더 최근인 값을 유지한다. 최근 레슨은 방문 시각을 비교하고 동률이면 현재 기기 기록을 우선한다. 파이썬 과거 점수는 숨긴 채 보존한다. 테마 가져오기 선택은 기본 해제 상태이며 선택하지 않으면 현재 테마를 유지한다.

`progress-transfer.js`는 자료 생성·입력 검증·병합·저장 실패 복구를, `transfer-ui.js`는 설정의 내보내기·미리보기·가져오기를 담당한다. 입력 자료와 기존 저장값을 검증하고, 미리보기 단계에서 기록을 바꾸지 않으며, 저장 실패 시 변경 전 원문을 복구하는 흐름을 확인한다. `app.js`의 학습 화면 반영과 `theme.js`의 테마 적용도 함께 확인한다. 기능의 로컬 검증·병합·Pages 배포·공개 PC·모바일 브라우저 확인을 마쳤으며 실제 범위와 근거는 [검증 기록](../verification.md)에 따로 남긴다. 파이썬 기초 콘텐츠의 기존 공개 검증과 이번 기능의 검증을 혼동하지 않는다.

## 화면 설정을 이어서 수정할 때

`theme.js`가 스타일 로드 전에 저장한 테마를 복원하고, `app.js`의 설정 경로에서 선택 화면을 렌더한다. `themes.css`는 다크 화면만 덮어쓰며 `settings.css`는 설정 카드 배치를 담당한다. 수학 SVG는 `visuals.js`의 `--visual-*` 변수와 기존색 fallback으로 즉시 테마를 따라간다. 학습 기록의 저장 키와 테마 키를 섞지 않는다. `designs/dark/`는 최초 비교 시안 보관용이며 운영 테마 파일과 독립적이다.

파이썬 분야 홈의 챕터 목차는 기본적으로 접혀 있다. 챕터 카드 전체를 누르면 해당 레슨 목록과 전체 목차·복습 링크가 펼쳐지고 다시 누르면 접힌다. 이 방식은 이후 추가 챕터에도 적용하며, 개별 챕터 페이지의 전체 목차와 기존 레슨 URL·읽음 기록은 유지한다.
