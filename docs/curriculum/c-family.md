| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 이 대분류 안에 **C++ 트랙(ch01~ch09)**과 **C# 트랙(ch10~ch18)**을 둔다. C#의 첫 챕터는 ch10이지만 C++ ch01~ch09를 선수 조건으로 요구하지 않는다. 표시 번호는 식별과 정리를 위한 것이며 두 언어의 학습 우선순위를 확정하지 않는다.
- C++와 C#을 문법만 다른 같은 언어로 설명하지 않는다. C++의 객체 수명·RAII와 C#의 GC·IDisposable을 각 런타임의 책임으로 구분한다. C 언어 별도 완주는 범위 밖이다.
- 타입·함수·컨테이너·객체·오류 처리의 언어별 표현은 여기서 깊게 다룬다. 복잡도와 자료구조 자체의 원리는 [알고리즘·자료구조](algorithms.md), 책임·추상화·설계 변경은 [개체지향·설계](object-design.md)의 주 범위다.
- 언어 도구의 디버거·테스트 연결은 이 과목에서 실제 프로그램에 적용한다. 디버깅 전략과 테스트 설계 전체는 [디버깅·테스트](debugging-testing.md)에서 확장한다.
- 파일 스트림·경로·직렬화 사용법은 해당 언어에서 다루되 포맷·인코딩·스키마 설계는 [데이터 파일 다루기](data-files.md)로 연결한다. C#의 HTTP 호출은 클라이언트 기능의 작은 적용이며 프로토콜·인증·SDK 설계 전체는 [HTTP·API·SDK](http-api-sdk.md)가 소유한다.
- **설계 제안**: C++는 C++20 기능을 지원하는 컴파일러와 CMake 기반으로, C#은 지원되는 안정 .NET SDK와 대응 언어 버전으로 집필한다. 구현 시 실제 버전·플랫폼·표준 라이브러리 지원 여부를 공식 문서로 확인한다. 특정 IDE 구매나 한 운영체제를 필수로 만들지 않는다.
- 실무 상한은 작은 콘솔 도구/재사용 라이브러리의 설계·빌드·확인·수정이다. 게임 엔진, GUI 프레임워크, ASP.NET 전체, 임베디드 드라이버, 잠금 없는 알고리즘, 템플릿 메타프로그래밍 전문 과정은 제외한다.
- 모든 레슨은 간단한 예제 5개, 각 챕터는 별도 복습 10개를 갖도록 후속 집필한다. 지금은 문제와 코드를 작성하지 않는다.

## 후속 집필 주의

- C++의 undefined behavior는 특정 출력 예측 문제로 만들지 않는다. 잘못된 수명·범위 접근을 식별하고 이유를 설명하는 문제로 다룬다.
- C++는 RAII와 표준 컨테이너를 기본으로 가르치며 수동 new/delete를 먼저 강제하는 구조를 피한다. 컴파일러의 경고·sanitizer 지원은 플랫폼별로 확인한다.
- C#은 참조 타입 변수의 일반 인자 전달과 ref 인자를 구분하고, GC와 IDisposable을 같은 기능으로 설명하지 않는다.
- C++ 표준·컴파일러와 C# 언어·SDK 버전은 각 트랙의 첫 화면과 예제에 기록한다. 신기능이 핵심 원리에 불필요하면 최신 문법을 강제로 추가하지 않는다.
- CMake·NuGet·테스트 도구의 명령은 공식 문서 확인 후 작성한다. 테스트 프로젝트·빌드 성공·실행 확인은 서로 다른 검증 단계다.
- 고급 템플릿 기법·unsafe 포인터·사용자 정의 메모리 할당자·복잡한 동시성 라이브러리는 기본 완료 조건으로 넣지 않는다. 게임/웹 프레임워크를 추가하려면 별도 범위를 정한다.
- 두 트랙의 완료 상태와 진행률을 나눌 수 있도록 후속 구현에서 내부 트랙 구조를 보존한다. 현재 계획 문서의 전역 레슨 ID는 재배열해도 변경하지 않는다.
