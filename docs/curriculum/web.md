# 웹

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `web` |
| 범위 | 기초→실무 |
| 목표 | 브라우저 화면에서 서버·저장소까지의 흐름을 이해하고 작은 반응형 웹 서비스를 만들고 고칠 수 있다. |
| 진입 지식 | 파일과 폴더를 다루는 기본 조작. JavaScript 기초는 이 과목 안에서 다룬다. 서버 챕터에 진입할 때 선택한 서버 언어의 함수·컬렉션·모듈 개념만 필요하다(`python` 등). |
| 완료 기준 | PC·모바일과 키보드에서 동작하는 작은 목록 관리 웹을 구성하고, 입력 검증·저장·오류 표시·배포 확인·작은 변경의 회귀 확인을 설명하고 수행한다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 프런트엔드의 문서 구조·레이아웃·상태·상호작용과 작은 웹 서버의 연결을 소유한다. 한 기능을 화면→요청→서버→데이터→화면으로 따라갈 수 있게 구성한다.
- HTTP 의미론, 인증 프로토콜, API 소비의 재시도·SDK 선택은 `http-api-sdk`에서 깊게 다룬다. 이 과목은 필요한 내용을 짧게 연결하고 화면·서버에 적용한다.
- SQL의 조인·트랜잭션 설계는 `sql`, 일반 테스트 설계는 `debugging-testing`, 배포 환경 자체의 운영은 `linux`, 협업·CI 플랫폼 조작은 `github`가 소유한다.
- 실무 상한은 한 사람이 이해하고 유지할 수 있는 작은 서비스다. 대규모 분산 시스템, 결제 처리, 대형 프레임워크 내부 구현, 클라우드 자격시험 범위는 제외한다.
- 설계 제안: 첫 화면은 HTML/CSS/JavaScript 표준 기능으로 만든다. 서버 단계에서 경량 프레임워크 하나와 소형 관계형 저장소 하나를 정하고 구현 시 공식 문서 버전을 확인한다. 특정 제품이나 프레임워크의 채택은 사용자 확정 사항이 아니다.

## 후속 집필 주의

- 레슨별 예제는 결과 예측·이유 설명·작은 오류 수정·레이아웃/상태 적용을 합쳐 5개로 구성한다. 완성품 복제보다 한 동작의 원인을 이해하게 한다.
- 프레임워크를 선택하면 선택 이유와 기준 버전을 적는다. 동일 개념을 여러 프레임워크 문법으로 반복하지 않는다.
- 접근성은 마지막 체크리스트에만 두지 않고 HTML·CSS·이벤트 레슨부터 포함한다. 모바일은 PC 동작을 작은 화면에 축소한 것으로 취급하지 않는다.
- 인증·암호·결제 시스템 직접 제작을 입문 실습으로 넣지 않는다. 보안은 방어 관점의 작은 예시를 검증된 구성요소와 연결한다.
