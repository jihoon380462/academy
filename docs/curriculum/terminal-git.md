# 터미널·Git

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `terminal-git` |
| 범위 | 기초→실무 |
| 목표 | 명령줄에서 작은 작업을 조합하고 코드 변경 이력을 이해·기록·복구할 수 있다. |
| 진입 지식 | 파일과 폴더의 기본 개념. 프로그래밍 언어 선행이나 리눅스 과목 완주는 필요하지 않다. |
| 완료 기준 | 작은 작업 스크립트와 저장소에서 변경 분리·충돌 해결·원격 동기화·실수 복구를 수행하고 어떤 이력이 바뀌었는지 설명한다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 터미널의 입출력·경로·인자·셸 조합과 Git의 작업 트리·스테이징·커밋·브랜치·복구를 소유한다.
- 리눅스의 사용자·권한·서비스·패키지 운영은 `linux`, 프로세스·파일시스템 내부 원리는 `operating-systems`, GitHub의 PR·이슈·CI 화면은 `github`가 소유한다.
- 명령을 무작정 외우기보다 실행 전 상태와 실행 후 상태를 비교한다. 공유 이력과 개인 이력에서 허용되는 수정의 차이를 설명한다.
- 실무 상한은 개발자가 일상 작업을 반복 가능하게 수행하고 저장소 상태를 관리하는 수준이다. 셸 전체 언어 명세, 대규모 저장소 서버 운영, Git 내부 객체 구현은 제외한다.
- 설계 제안: 기본 예시는 Bash 호환 셸과 Git CLI를 사용한다. Windows의 PowerShell과 문법이 같다고 가정하지 않으며, 구현 시 사용 환경·버전을 명시한다. 실제 사용자 폴더 대신 연습 디렉터리와 별도 저장소를 사용한다.

## 후속 집필 주의

- 매 레슨의 예제 5개는 명령을 입력하기 전 상태 예측과 출력·차이 읽기를 중심으로 만든다. 위험한 명령은 설명 없이 복사하게 하지 않는다.
- Git과 GitHub를 같은 프로그램처럼 소개하지 않는다. 원격 실습은 GitHub 계정 사용이 없어도 개념을 읽을 수 있게 작성한다.
- 복구 레슨은 별도 연습 저장소를 사용한다. 공유 이력을 강제로 덮어쓰는 과정은 영향과 대안을 함께 판단하게 한다.
- 셸 예시에는 Bash 기준 여부를 표시하고 실제 환경의 도움말·버전을 확인한다. 사용자 비밀값이나 개인 파일 경로를 정답에 요구하지 않는다.
