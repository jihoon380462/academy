# 어셈블리어

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `assembly` |
| 범위 | 기초→실무 |
| 목표 | 짧은 기계 수준 실행 흐름을 읽고, 레지스터·메모리·호출규약을 근거로 작은 함수의 오류를 조사한다. |
| 진입 지식 | `cs`의 비트·정수·메모리 주소, 변수·조건·반복·함수 읽기. 중반에는 `c-family`의 C++ 기본 타입·배열·포인터 개념을 필요한 만큼 연결한다. |
| 완료 기준 | 자신이 만든 작은 C/C++ 함수의 디스어셈블리를 소스와 연결하고, 레지스터·스택·메모리 변화를 추적해 경계나 호출 관련 오류 한 가지의 원인을 설명한다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 설계 제안: x86-64, Linux 사용자 공간, System V AMD64 ABI, Intel 표기법을 한 기준 조합으로 사용한다. 본문 구현 시 컴파일러·어셈블러·GDB 버전과 ABI 문서를 확인한다. 사용자가 확정한 플랫폼 선택은 아니다.
- 명령어 읽기·작은 루틴·메모리 접근·함수 호출·오브젝트/링크·디버깅이 주 범위다. 실무 상한선은 자신의 작은 바이너리와 성능/오류의 국소 원인을 읽어 설명하는 수준이다.
- `cs`는 실행 계층 개요, `operating-systems`는 자원관리·시스템 호출의 원리, `c-family`는 언어 규칙·컴파일·수명, `debugging-testing`는 재현과 검증 절차를 맡는다. 어셈블리에서는 기계 수준 근거를 보탠다.
- Windows x64 ABI와 ARM64는 같은 레지스터·호출규칙을 쓰지 않음을 경계 설명으로 소개하되 별도 병렬 트랙을 만들지 않는다. 운영체제 부트로더·드라이버·전체 명령어 암기·고급 SIMD 최적화·상용 바이너리 우회/공격은 필수 범위 밖이다.

## 후속 집필 주의

- 예제마다 ISA·ABI·표기법·컴파일러 옵션을 표시한다. 운영체제만 같으면 ABI도 모두 같다고 표현하지 않는다.
- 초반에는 정수·짧은 함수·작은 배열을 사용한다. 부동소수점/벡터 명령은 별도 확장이며 기초 설명에 섞어 난도를 올리지 않는다.
- 화면 그림의 레지스터·주소·스택 변화는 실제로 재현 가능한 결과로 검증한다. 최적화나 플랫폼 차이로 달라질 수 있는 부분은 고정 법칙처럼 쓰지 않는다.
- 직접 어셈블리 구현은 작은 루틴만 다룬다. 목적은 일반 코드를 전부 어셈블리로 다시 쓰는 것이 아니라 낮은 수준의 실행 근거를 읽는 것이다.
