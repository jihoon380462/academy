# GitHub

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `github` |
| 범위 | 기초→실무 |
| 목표 | 저장소의 변경을 이슈·PR·검토·자동 검사·릴리스로 연결하고 작업 의도를 남길 수 있다. |
| 진입 지식 | Git의 커밋·브랜치·원격 개념(`terminal-git`의 해당 부분). 모든 Git 고급 기능이나 CLI 숙련은 필요하지 않다. |
| 완료 기준 | 작은 저장소에서 이슈 하나를 PR로 해결하고 자동 검사 결과와 리뷰를 반영해 병합·릴리스하며 다음 사람이 재현할 안내를 남긴다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- GitHub 플랫폼에서의 저장소 탐색·작업 추적·PR 검토·자동 검사·릴리스와 유지관리 흐름을 소유한다.
- Git 명령·충돌·이력 복구의 원리는 `terminal-git`, 실제 테스트 전략은 `debugging-testing`, 배포 대상 앱 구성은 `web` 또는 해당 언어 과목에서 다룬다.
- 실무 상한은 개인 또는 작은 팀 저장소를 지속적으로 관리하는 수준이다. 대기업 조직 정책, 과금 최적화, 대규모 자체 실행기 운영, 모든 부가기능은 제외한다.
- 설계 제안: 웹 UI를 기본으로 개념을 보여 주고 CLI는 같은 작업의 선택 경로로 연결한다. 요금제·공개 범위에 따라 달라지는 기능은 집필 시 공식 문서로 확인하며 유료 기능을 필수로 정하지 않는다.

## 후속 집필 주의

- 각 레슨의 5개 예제는 화면의 상태 해석·diff 읽기·다음 행동 선택·짧은 설명 작성으로 설계한다. 계정의 실제 권한 변경이나 공개 게시를 정답 조건으로 요구하지 않는다.
- 실습은 별도 연습 저장소를 기준으로 하며 사용자 저장소를 공개로 전환하는 절차를 기본값으로 넣지 않는다.
- 화면 위치·버튼 이름·기능 제공 범위는 변경될 수 있으므로 집필 시 공식 문서와 실제 UI를 확인한다. 개념은 UI 위치보다 오래 유지되는 역할 중심으로 설명한다.
- Actions 예시는 자동 검증까지만 먼저 구성하고 배포·비밀값 권한은 필요한 단계에서 구분한다. 현재 학습 사이트에 즉시 CI를 도입하라는 지시가 아니다.
