# AI와 협업

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `ai-collaboration` |
| 범위 | 기초→실무 |
| 목표 | AI에게 목표·범위·맥락을 전달하고, 결과를 직접 확인하며 작은 개발 작업을 완료한다. |
| 진입 지식 | 파일과 코드의 기본 구조를 읽는 능력. 구현 예에서는 `python` 또는 `c-family`의 관련 문법만 필요하며, LLM 내부 이론과 유료 도구 구독은 선행 조건이 아니다. |
| 완료 기준 | 작은 기능이나 결함 수정에 대해 작업 명세·관련 맥락·변경 검토·실행 검증·인수인계 기록을 남기고, AI의 주장과 관찰된 결과를 구분한다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 요구사항 정리, 맥락 관리, 작은 작업 분할, 변경 검토, 검증, 실패 대응과 재개 가능한 기록을 다룬다. 실무 상한은 개인 또는 소규모 저장소에서 AI와 기능을 만들고 유지하는 수준이다.
- `llm-basics`는 모델·토큰·생성의 원리를, `http-api-sdk`는 모델을 포함한 외부 API 연결을, `debugging-testing`은 실제 검사 기법을 소유한다. 이 과목은 그 도구와 증거를 협업 과정에서 언제 요구하고 해석할지 다룬다.
- 자율 에이전트 프레임워크 제작, 모델 학습·파인튜닝, 대규모 다중 에이전트 운영, 특정 모델 순위·요금 암기는 제외한다. AI가 대신 작성한 코드의 실행 결과를 확인하는 책임까지 자동으로 사라진다고 가르치지 않는다.
- 설계 제안: 일반 채팅·편집기 보조·저장소 작업 에이전트의 공통 흐름을 사용한다. 서비스별 메뉴·권한·제품 기능은 집필 시 공식 문서로 확인하고 특정 제품 가입을 필수로 만들지 않는다.

## 후속 집필 주의

- 레슨별 예제 5개는 요청 비교·누락된 맥락 찾기·변경 검토·증거 분류·다음 행동 선택으로 구성하고 챕터 복습은 10개로 유지한다.
- 특정 모델 이름·상품 요금·기능 비교를 핵심 목차에 고정하지 않는다. 한 번 통했던 프롬프트를 보편적인 성공 공식으로 제시하지 않는다.
- AI에게 일을 맡기는 과정에서도 사용자가 최종 요구사항과 품질을 판단할 수 있게 설명한다. 학습자가 직접 수정·확장할 여지를 남긴다.
