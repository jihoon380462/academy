# 운영체제

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `operating-systems` |
| 범위 | 기초→실무 |
| 목표 | 실행·메모리·저장·동시성의 원리를 연결하고, 관찰 자료로 작은 프로그램의 자원 문제를 설명한다. |
| 진입 지식 | 초반은 `cs`의 CPU·메모리·프로그램 개념. 실측 단계는 변수·함수·반복 코드 읽기와 `terminal-git`의 명령 실행·출력 읽기만 필요하다. |
| 완료 기준 | 작은 프로그램의 CPU 사용·대기·메모리·파일 상태를 관찰해 원인 가설을 세우고 한 조건씩 바꾸어 검증한 진단 기록을 만든다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 프로세스·스케줄링·가상 메모리·동기화·파일 시스템·입출력·격리 원리를 맡는다. 실무는 사용자 공간 프로그램의 관찰과 진단까지이며 커널 자체 개발이 목표가 아니다.
- `linux`는 계정·패키지·서비스·네트워크·백업의 실제 운영, `terminal-git`는 셸 문법·명령 조합과 Git을 맡는다. 여기서는 명령을 원리 관찰 도구로만 짧게 사용한다.
- 동시성 구조를 만드는 언어 API는 `python-practice` 또는 `c-family`, 명령어와 ABI는 `assembly`, 일반 재현·테스트 전략은 `debugging-testing`에서 깊게 다룬다.
- 관찰 환경은 Linux 사용자 공간을 설계 제안으로 삼고 구현 시 공식 문서와 배포판·커널·도구 버전을 확인한다. 보편 원리와 Linux 고유 동작을 구분한다. Windows 전체 내부 구조, 드라이버, 실시간 커널, 분산 OS 구현은 제외한다.

## 후속 집필 주의

- 스케줄러·메모리 회수 정책의 특정 구현을 운영체제 일반 법칙으로 설명하지 않는다. 원리 도식과 관찰 환경을 명확히 표시한다.
- 시스템 상태 변경은 별도 실습 환경을 전제로 설계한다. 문서의 주된 예제는 작은 사용자 프로세스와 읽기 중심 관찰이며 실제 명령·실행기는 이번 뼈대에 넣지 않는다.
- 동시성 예제는 재현되지 않는 한 번의 실행을 정답 근거로 삼지 않는다. 실행 순서 도식과 보장 조건을 먼저 검증한다.
