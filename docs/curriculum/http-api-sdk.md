# HTTP·API·SDK

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `http-api-sdk` |
| 범위 | 기초→실무 |
| 목표 | 요청과 응답을 해석하고 API 문서에 따라 서비스를 연결하며 실패를 다룰 수 있다. |
| 진입 지식 | 한 언어의 함수·컬렉션·오류 처리 개념(`python` 또는 `web`의 JavaScript 기초). HTTP 자체는 처음부터 다룬다. |
| 완료 기준 | 문서가 있는 API에서 페이지별 데이터를 가져오고, 인증·타임아웃·오류·호출 한도를 처리하며 SDK와 직접 HTTP 호출의 차이를 설명한다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- 통신 계약과 서비스 소비를 소유한다. HTTP 요청·응답, API 문서 읽기, 인증 적용, SDK 사용, 실패 처리 및 관찰이 중심이다.
- 서버 라우팅과 실제 업무 기능 구현은 `web`, 일반 비동기 언어 문법은 `python-practice` 또는 `web`, 파일 형식의 깊은 처리는 `data-files`에서 다룬다.
- API 테스트의 계약 사례는 여기서 다루되 일반 테스트 전략·모킹 원리는 `debugging-testing`에 연결한다. 네트워크 계층의 내부 동작은 `cs`에 연결한다.
- 실무 상한은 작은 서비스 연동을 신뢰할 수 있게 운영하는 수준이다. 네트워크 프로토콜 구현, 암호 프로토콜 개발, API 게이트웨이의 대규모 운영은 제외한다.
- 설계 제안: raw 요청 관찰 도구 하나와 이미 배운 언어의 HTTP 클라이언트 하나를 사용한다. SDK 사례는 공개 문서와 테스트 환경이 있는 서비스로 집필 시 선정하고 버전을 확인한다. 유료 계정이나 실제 비밀값 제출을 학습 필수조건으로 만들지 않는다.

## 후속 집필 주의

- 레슨마다 예제 5개는 요청/응답 읽기·실패 원인 판단·작은 호출 수정에 배분한다. 실제 토큰이나 유료 호출 없이 검증 가능한 샘플을 제공한다.
- HTTP 메서드와 재시도는 단순 암기표에 그치지 않는다. 멱등성은 의도한 서버 효과 기준이며 응답이 항상 같다는 뜻은 아니라는 점을 유지한다.
- 브라우저의 CORS, 서버 인증 실패, 네트워크 실패를 다른 층위로 설명한다. 보안 정책 끄기를 일반 해결법으로 가르치지 않는다.
- API 제공자·SDK별 인증 방식과 자동 재시도 정책은 집필 시 공식 문서 버전을 확인한다. 특정 서비스의 정책을 모든 API의 규칙으로 일반화하지 않는다.
