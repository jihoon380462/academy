# vim

| 항목 | 설계 |
| --- | --- |
| 과목 ID | `vim` |
| 범위 | 기초→실무 |
| 목표 | 모드와 편집 명령의 조합을 이해하고 여러 파일의 반복 수정과 복구를 수행할 수 있다. |
| 진입 지식 | 파일 경로와 터미널에서 프로그램을 여는 조작(`terminal-git`의 첫 부분). 프로그래밍 언어 선행은 필요하지 않다. |
| 완료 기준 | 설정이나 코드 파일 여러 개를 열어 탐색·검색·치환·반복 수정하고 변경을 확인한 뒤 저장하며, 실수나 중단에서 복구할 수 있다. |
| 콘텐츠 상태 | 설계만 완료, 본문 미작성 |

## 범위와 과목 경계

- Vim의 모드·이동·연산자·텍스트 객체·검색·버퍼·창·반복·기본 설정을 실제 편집 흐름으로 다룬다.
- 셸 명령과 Git 이력은 `terminal-git`, 운영 환경·권한은 `linux`, 프로그래밍 문법과 코드 설계는 각 언어 및 `object-design`에서 다룬다.
- 실무 상한은 플러그인 없이도 파일을 안정적으로 읽고 고치며 필요한 최소 설정을 유지하는 수준이다. Vimscript 플러그인 개발, 편집기 프레임워크 구축, 모든 명령 암기는 제외한다.
- 설계 제안: 기본 Vim과 내장 도움말을 기준으로 한다. Neovim이나 특정 IDE의 Vim 모드는 동일 환경으로 간주하지 않으며 별도 확장이 필요할 때 차이를 밝힌다. 설치된 버전과 키보드 입력 환경은 구현 시 확인한다.

## 챕터와 레슨

### vim-ch01 · 모드와 파일의 생명주기

- 도달점: 입력·명령·저장을 구분하고 실수 없이 편집을 시작하고 끝낸다.
- 선행: 터미널에서 파일 경로 지정.

| 레슨 ID | 레슨 | 이해·수행 목표 |
| --- | --- | --- |
| `vim-l001` | Vim의 모드 | 키가 문자 입력인지 명령인지 결정하는 상태를 구분한다. |
| `vim-l002` | 열기·입력·모드 전환 | 파일을 열고 짧게 편집한 뒤 기본 모드로 돌아온다. |
| `vim-l003` | 저장·종료·취소 | 현재 버퍼와 저장된 파일의 차이를 확인해 종료한다. |
| `vim-l004` | 되돌리기와 다시 실행 | 실수한 변경을 되돌리고 복원한다. |
| `vim-l005` | 도움말과 tutor | 기억나지 않는 동작을 내장 도움말에서 찾는다. |

- 복습 10문제 설계: 모드 예측 3·파일 상태 3·작은 편집 3·종료 판단 1. 저장하지 않은 버퍼와 디스크 파일을 구분한다.

## 후속 집필 주의

- 매 레슨의 5개 예제는 모드·커서·버퍼 상태를 제시하고 다음 변화와 적용 범위를 예측하게 한다. 빠른 입력이나 명령 암기량을 성취 기준으로 삼지 않는다.
- 키 표기를 일관되게 사용하며 Esc·Ctrl 조합과 입력할 문자를 구분한다. 모바일에서는 설명·화면 상태·풀이를 읽을 수 있게 하고 실제 편집기 조작은 PC 선택 실습으로 둔다.
- 파일을 덮어쓰는 실습은 복제한 작은 텍스트 파일로 진행한다. 복구 가능성은 버퍼·스왑·파일 저장·Git 기록별로 구분한다.
- 플러그인을 설치해야만 따라갈 수 있는 레슨은 기본 범위에 넣지 않는다. 선택 확장은 원리와 기본 편집 능력 이후 별도 결정한다.
