## 복원 전에 확인할 것

1. 되돌리려는 대상과 백업 기준을 먼저 정한다. 점진 연습 도입 전으로 돌아가려면 `2444a18`, 점진 연습 시범을 유지하면서 이번 코딩 간소화만 되돌리려면 `c84cf29`를 검토한다. 챕터 1 콘텐츠만 복원할지 관련 구현도 되돌릴지 정하고 이후 변경을 확인한다.
2. `git status --short`로 작업 트리를 확인하고 아직 보존하지 않은 작업을 먼저 보존한다. 백업을 현재 작업 폴더 위에 통째로 풀지 않는다.
3. 압축 파일을 사용할 때는 SHA-256을 대조하고 별도 임시 폴더에 풀어 `manifest.json`의 파일별 해시와 비교한다. 이 압축 파일은 소스 스냅샷이며 `.git` 이력을 포함한 저장소 복제본은 아니다.
4. 공유한 이력은 강제 reset·force push로 덮어쓰지 않는다. 최신 상태에서 별도 복원 브랜치를 만들고 필요한 변경만 검토한다.

## 챕터 1 콘텐츠만 선택해 복원하기

아래는 현재 작업을 보존하고 최신 `origin/main`을 확인한 뒤, 점진 연습 도입 전 콘텐츠를 별도 브랜치에서 복원하는 예시다. 코딩 간소화 직전 콘텐츠를 선택하려면 fetch할 백업 브랜치를 `backup/python-ch01-before-coding-fix-20261112-c84cf29`, 복원 기준 SHA를 `c84cf295f9ff8c8cd5e780eba5833fb3d5baa759`로 바꾸고 별도 브랜치 이름을 사용한다. 이 문서 작성 과정에서 복원 명령을 실행한 것은 아니다.

```bash
git status --short
git fetch origin main backup/python-ch01-before-training-20261112-2444a18
git switch -c restore/python-ch01-before-training origin/main
git restore --source=2444a18bf4260c1a003183d209a3f5b2d1d6843e -- content/python/ch01/
python3 build-python.py --check-code
git diff -- content/python/ch01/ python-content.js
```

이 방법은 원본 챕터 1을 가져온 뒤 **현재 나머지 챕터를 유지한 채** `python-content.js`를 다시 생성한다. 예시 답의 코드·예상 결과·문항 요구와 화면을 확인하고, 기존 URL·읽음·최근 레슨·과거 점수·테마 보존을 검증한 뒤 복원 변경을 커밋·PR로 검토한다. 실제 배포 여부와 공개 확인도 별도로 기록한다.

앞선 점진 연습 시범의 로컬 검증에서 당시 원본과 초기 `2444a18` 백업의 챕터 1 JSON 6개를 당시 빌더가 수용함을 확인했다. 이번 코딩 간소화의 로컬 검증에서도 두 백업 형식을 빌더가 허용하고 각각 74개 렌더 결과를 보존함을 확인했다. 이 호환 검사만으로 실제 복원을 수행하거나 공개한 것은 아니다. 실제 복원은 별도 브랜치에서 변경 범위를 검토한 뒤 수행한다. 공통 UI·빌더가 이후 바뀌었을 수 있으므로 복원 시점의 코드가 선택한 백업의 콘텐츠 형식을 어떻게 처리하는지도 확인한다. `python-ui.js`·공통 스타일·다른 챕터·CS·학습 기록 파일을 백업판으로 무조건 덮어쓰지 않는다. 공통 코드의 일부를 되돌려야 한다면 해당 변경과 이후 변경을 비교해 필요한 부분만 별도 처리한다.

## 관련 구현까지 되돌리려면

되돌릴 개정의 구현 커밋을 먼저 특정하고, 그 이후 같은 파일에 추가된 작업까지 검토한 뒤 `git revert`로 되돌리는 변경 커밋을 만드는 방법을 우선 검토한다. 병합 커밋을 대상으로 할 경우 부모 관계도 확인해야 한다. 충돌이나 범위가 섞인 변경은 위의 별도 브랜치·선택 복원 방식으로 나누어 검토한다.

백업 브랜치는 처음 보존한 커밋을 유지하고, 복원 결과는 새 커밋으로 남긴다. 앱 버전·자산 캐시·기록 저장 키는 [버전 관리 규칙](../VERSIONING.md)에 따라 각각 관리하며 복원 때문에 기존 학습 기록 키를 바꾸지 않는다.
